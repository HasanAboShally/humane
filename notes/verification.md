## What the checks mean

- **Repository checks:** validate the instruction format, content budgets, source links, fixtures, license, and packaging boundaries. They do not measure reading quality.
- **Installer checks:** establish that the existing installer discovers and places the right bytes in client skill locations. They do not prove that a client invokes the skill correctly.
- **Model smoke tests:** exercise fictional scenarios with an assistant and inspect the response. A small set of successful outputs is not a reliability guarantee or a human study.
- **Human reader tests:** not conducted. No measured speed, comprehension, or “10x” claim is supported.

## Prerelease review recommendations before launch approval

This review preceded the owner's explicit v0.1.0 publication approval. It remains as the original recommendation, not a current prohibition or a claim that every research task is a launch gate. Client-invocation and human-reader limitations still apply to the experimental release. The [launch record](release-v0.1.0.md) supersedes its availability and deployment status.

Freeze the current skill rather than append more speculative rules. Metadata, packaging and the website already have working checks. The useful remaining work is:

- Test actual invocation and a few real tasks in the one or two clients initially advertised as supported. Include ordinary requests without the skill name and an unrelated task that should not trigger it. Discovery and installer placement are not substitutes for this check; wider client support can remain unverified.
- Use the [small reader pilot](design.md#small-human-reader-pilot) to compare Humane with a plain prompt on the same model. Start with 5–8 intended readers and blinded, matched tasks. An explicitly experimental release need not promise measured gains; stronger claims require evidence.
- Resolve the account restriction and obtain a successful hosted checks run. Do not weaken tests or change visibility to bypass it.
- After explicit publication approval, choose what becomes public: source repository, site and/or downloads. Review repository history before making all source public, create a stable versioned release with checksums, and verify fresh installation through the chosen public route. No tags or releases have been created by this review.
- Make the release copy and crawler settings match that choice. The current Pages workflow deliberately keeps indexing disabled; merely enabling its publication gates will not remove noindex or create a sitemap. Follow [the release-specific search checks](search-readiness.md#only-after-public-launch-approval), then verify live URLs and downloads. Do not change these controls while the preview is private.

No new modes, reader profiles, runtime service, analytics or further compression is justified by this audit. The skill and website source were left unchanged. The current state is suitable for invited testing; this review is not authorization to publish.
