# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

Delegated by the owner on 17 September 2026: build directly using judgment, with a lightweight static HTML/CSS/JavaScript site prepared for GitHub Pages. Keep the portable Markdown skill independent of the website and its build tools.

## Users

People who receive documents, messages, or reports they must understand and check, and people preparing material that others must read. The audience includes nontechnical readers as well as people using coding assistants.

## Product Purpose

Help an existing assistant make human-facing content easier to understand without hiding evidence, uncertainty, or important conditions. Receiver tasks produce a coherent brief; sender tasks produce considerate content; version comparisons require an actual baseline.

## Capabilities and Constraints

One installable Agent Skill. No accounts with Humane, hosted model, automatic file access, converter, analytics, or backend. Runtime behavior and privacy depend on the user's assistant. Copying the instructions into a chat or manually installing the skill folder requires neither Node.js nor Git; those tools belong to the optional Skills CLI installation route, not the skill's runtime. A skill-only ZIP is also generated for upload-capable clients. Skill invocation and file support vary by client.

On 22 September 2026 the owner approved a public repository with one initial commit, the experimental v0.1.0 release, and the GitHub Pages website and downloads. This supersedes the earlier local-preview-only restriction. Preserve the development history and pending edits in a private backup outside the public repository before rewriting main. No domain registration, DNS changes, directory submission, or marketing campaign is included.

Keep the default build and local server unindexed. Only the explicitly approved public Pages build enables indexing and emits a sitemap. Metadata must describe the actual Markdown skill, not a hosted application or unearned reviews. Agent-readable exports must retain the visible content's source, privacy and compatibility limits; rankings and AI citations are not promised.

## Brand Commitments

Humane is the working name. The owner asks for an outstanding, futuristic site that still feels humane and simple. Language should demonstrate care for the reader, avoid hype, and state what actually exists. Keep the creator credit direct; do not add speculative affiliation disclaimers.

The owner approved the visual design and then requested an English-only website with less repetition and more direct explanations. Name the originals and example responses explicitly. Prefer removing redundant sections over inventing new slogans. This website decision does not restrict the skill's ability to respond in the user's requested language.

Light appearance is the first-visit default while honoring explicit saved dark/light choices. Keep dark paper layers visibly distinct. Identify MIT as an open-source license and the release as experimental, not a certification of model behavior.

The owner rejected the neutral light-surface experiment as too gray and requested restoring the original green-tinted palette. Keep the green page, paper and section tones; do not reintroduce neutral gray surfaces without a new request. The dark palette, layout, copy and subtle animation remain unchanged.

The owner subsequently rejected the repeated expansion/contraction and allowed a return to the original subtle motion. Restore that short, gentle rotation/fade rather than adding a library to decorate the same pulse. Keep replay text absent, reading text still, and reduced-motion support intact. The SEO and asset-size work must remain unchanged.

The owner rejected the hero's defensive “not a separate AI service” clarification and generic task list. Name the free Agent Skill positively, then communicate the reader's burden and a concrete result: one coherent explanation across documents with a way back to the originals. Do not turn each conversation clarification into website text. Preserve the defining idea and voice, not just correct category labels. Sender use remains visible in the writing example and setup rather than squeezing every capability into the introduction.

## Product Principles

- Reduce reconstruction, not critical thinking.
- Keep necessary caveats beside the claim they qualify.
- Preserve source context and disclose what was not read.
- Use ordinary requests, not special modes or mandatory markup.
- Keep the first interaction useful without an account or form.

## Accessibility and Inclusion

The website should be usable with a keyboard, a screen reader, reduced motion, narrow screens, and larger text. Its content is English-only by the owner's explicit decision. Readability and accurate claims take priority over ornamental effects. The portable skill remains language-flexible.
